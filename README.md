# AI営業社員のデモ（02 営業準備 → 03 アプローチ）

アスリートのマネジメント、動画制作、SNS運用代行を行う**架空の会社**の営業として、AI社員が「狙う相手を決める → 営業リスト → 下調べ → 連絡文の下書き → 品質チェック → 承認待ち → 送付と追いかけ → 返信の仕分け → 効果測定」を行うデモです。

- すべての画面に「AIがすること」と「人が確認すること」を表示します
- 会社、人物、出来事、実績の数字はすべて架空です。実在のサイトにはアクセスしません
- メール、フォーム、DMは実際には送信しません。SNSのDMは下書きまでで、自動では送りません
- APIキーがなくても、すべての機能が動きます（見本モード）

## 動かし方

```bash
npm install
npm run dev          # 開発用のサーバー（http://localhost:3000）
npm run build        # 本番用にビルド
npm test             # 単体テスト（Vitest）
npm run test:e2e     # 通しのテスト（Playwright。パソコンとスマートフォンの画面の大きさ）
BASE_URL=https://ai-sales-agent-demo.vercel.app npm run test:e2e   # 公開URLで確かめる
npm run data         # 架空のデータ（data/*.json）を作り直す
```

## 構成

| 場所 | 役割 |
|---|---|
| `data/companies.json`、`sources.json` | 架空の会社60社と、下調べの元になる架空の公開情報（144件） |
| `data/playbooks.json` | ナレッジ：共通のルール＋事業ごとの手引き3つ（狙う相手、強み、ひな形、言ってはいけない表現）、修正の理由 |
| `data/samples/` | 見本モードの完成形（主要な10社の下調べと書き出し）と、わざと問題を入れた下書き4件 |
| `data/replies.json`、`history.json` | 架空の返信12件と、過去2週間の送付の記録（効果測定の土台） |
| `src/lib/scoring.ts` | 採点と理由、除外リストと重複の除外 |
| `src/lib/research.ts`、`generate.ts` | 出典つきの下調べと、連絡文の下書き（メール、フォーム、DM、電話のメモ） |
| `src/lib/quality.ts` | 品質チェック8項目（根拠、誇大な表現、送信者の表示と配信停止の案内、宛先の一致、個人の情報、言ってはいけない表現、長さ、手段の規約） |
| `src/lib/knowledge.ts` | 手引きの適用と、承認の修正から加わったルール |
| `src/lib/replies.ts`、`followups.ts`、`metrics.ts` | 返信の仕分け、追いかけ、効果測定 |
| `src/lib/state.ts`、`store.ts` | 操作（純粋な関数）と、ブラウザの localStorage への保存 |
| `src/views/` | 各画面 |

データベースは使いません。操作の記録は、ブラウザの中（localStorage）だけに保存します。画面右上の「初期の状態に戻す」で消せます。

## 見本モードとAIモード

- **見本モード（今の動き）**：主要な10社は、品質の高い完成形を表示。それ以外の会社は、手引きのひな形と会社のデータから規則で組み立てます（「簡易作成」と表示）。返信の仕分けは、キーワードの規則です。
- **AIモード（本番）**：下調べ、連絡文、返信の仕分けをAIで作ります。キーはサーバー側の環境変数だけに置きます。出力は決まった形（JSON）で受け取り、**このデモと同じ品質チェックと出典の照合を必ず通し**、通らないものは止めます。
